## Probe anchors

Every registry variant carried a prose sentence as its `semanticAnchor` ("async spawnClaude(input,
rest)"), while the probe compares the anchor as a literal substring — so it reported `MISS` for
every point on every real bundle, 2.1.296 included, and told nothing about drift.

Each variant now also declares `anchorPattern`: the expression the patcher itself looks for, written
against structure rather than against the minified names of one release. The probe compiles it and
counts matches; `semanticAnchor` stays as the literal text of the release the anchor was taken from
and is used only when no pattern is declared. The registry validator rejects a pattern that does not
compile.

Because the patterns are the patcher's own expressions, the probe answers exactly what the current
patcher would apply, on every release those expressions cover:

| Pristine bundle | probe |
|---|---|
| 2.1.312 | `PASS 28 / MISS 0` |
| 2.1.296 | `PASS 28 / MISS 0` |

The adaptation suite's fixtures carry two shapes each, written the way the shipped bundle writes
them, and the suite scopes its registry by matching those patterns — fixture, probe and patcher stay
on one definition of "the anchor is there".

## Two shapes of one hook

`PATCH-HOST-ENV-FOR` matches the old assignment form and the new options-literal form. Both exist
in pristine 2.1.296 (two distinct code paths), only the literal form survives in 2.1.312. The
patcher expected exactly one hit, so 2.1.296 refused with "signature matched 2 times". `hits` may
now list every legitimate count (`[1, 2]` here), and each match is hooked at its own site.

Measured after the change:

| Bundle | patcher |
|---|---|
| pristine 2.1.296 | `patched extension.js (10 hook(s))`, `patched webview/index.js (18 hook(s))`, exit 0 |
| pristine 2.1.312 | same, exit 0 |

## Signatures that had to be forked

Four anchors from the previous range no longer matched; each was widened to accept the old and
the new shape (no existing variant was replaced):

| Point | Change in 2.1.312 | Anchor change |
|---|---|---|
| `PATCH-WEBVIEW-HTML-INJECT` | the module script tag gained an `id` attribute: `<script id="${d04}" nonce="${B}" src="${K}" type="module">` | the opening tag is captured whole instead of being rebuilt from the nonce |
| `PATCH-WEBVIEW-MODEL-ACTION` | config read renamed to `drawnClaudeConfig`; the resolved model takes a different third argument | `(?:drawn)?[Cc]laudeConfig` and a loose tail up to the registry call |
| `PATCH-WEBVIEW-MODEL-PILL` | `ultracode:<local>` sits between `effort` and `isOpen` | the properties in between are skipped rather than enumerated |
| `PATCH-HOST-ENV-FOR` | the session options are one object literal handed to the constructor (`…pathToClaudeCodeExecutable:Cf,env:$5,forkSession:a,…,resume:iH,resumeSessionAt:Pf`), so there is no options variable and no `env=` assignment | a second alternative: the hook rides on `resume:`, rebuilds the env object in place and returns the resume id `envFor` left behind |

`PATCH-HOST-BIND-NATIVE` (optional) has no anchor at all in 2.1.312 — the native producer binding
stays off for this release, which the optional flag allows.

## Findings

- **The probe used to verify nothing.** Its registry anchors were prose and it compares them as
  literal substrings, so `MISS` for every point on every shipped bundle was the only possible
  outcome. Fixed here: each variant declares `anchorPattern`, the patcher's own expression, which is
  written against structure and therefore survives re-minification — 28/28 on both 2.1.312 and
  2.1.296.
- **One anchor can legitimately match twice.** `PATCH-HOST-ENV-FOR` has two live shapes on
  2.1.286–2.1.296 and one on 2.1.312; the patcher now accepts a list of counts instead of refusing
  a bundle that carries both.
- **`PATCH-HOST-BIND-NATIVE` was off and is now on.** 2.1.312 wraps the launch in `.finally(...)`
  before taking `.query(`, so a single call chain no longer reaches the query from `{options:…}`.
  The anchor now skips that segment (it carries no semicolon, so the laziness cannot walk past the
  statement), and the binding is applied: `bindNativeProducer` is present in the patched bundle and
  absent from the pristine one, on both 2.1.312 and 2.1.296.
